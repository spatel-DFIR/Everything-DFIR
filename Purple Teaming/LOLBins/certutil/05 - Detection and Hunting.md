## Hunting Priority — Which Signal to Trust Most

`certutil.exe`'s abuse surface has one meaningful evasion knob the operator controls directly (renaming/relocating the binary — `02 - Hands-On Use Cases.md`'s "Renamed or Relocated Binary" scenario) and one the technique class controls (download verbs vs. purely local encode/decode verbs, which differ in whether any network/cache artifact exists at all). Rank hunts by what survives which:

| Rank | Signal | Survives binary rename/relocation? | Survives `-encode`/`-decode`-only (no network) use? | Notes |
|---|---|---|---|---|
| 1 (strongest) | `CryptnetUrlCache\MetaData\<hash>` / `Content\<hash>` entries (user or SYSTEM path) | ✅ Yes — the cache write is a side effect of certutil's own internal WinINet/CryptoAPI calls, not of the process's own file name | ❌ N/A — only generated by the download verbs | Directly recoverable download log (source URL, timestamp, size, hash) even with zero process-creation logging enabled |
| 2 | Command-line **argument shape** (`-urlcache`/`-verifyctl`/`-URL`/`-encode`/`-decode`/`-encodehex`/`-decodehex` + the `InFile OutFile` positional pattern) in Sysmon 1 | ✅ Yes — renaming the binary doesn't change how it parses its own arguments | ✅ Yes — this is the only rank-1-or-2 signal that also fires for encode/decode-only use | Requires Sysmon or 4688 command-line auditing deployed — without it, this rank is invisible, matching the caution in `Windows/Threat Landscape and Playbooks/LOLBIN Abuse Hunting Playbook.md` |
| 3 | Certutil-specific `User-Agent` strings (`Microsoft-CryptoAPI/10.0`, `CertUtil URL Agent`) in proxy/firewall/Zeek logs | ✅ Yes — the UA is generated by the underlying CryptoAPI/WinINet call, independent of the calling process's name | ❌ N/A — download verbs only | Valuable specifically because it doesn't require **any** endpoint telemetry — works from network logs alone |
| 4 | `Image`/file path check: certutil-shaped activity running from anywhere other than `System32`/`SysWOW64` | ❌ No — defeats itself if the operator runs the **unmodified** binary in place; only catches the copied/relocated variant | ✅ Yes | Combine with Authenticode/`OriginalFileName` verification to catch a renamed-but-still-genuine binary specifically |
| 5 (weakest) | Bare `certutil.exe` process-creation frequency/presence | ❌ No | ❌ No | High false-positive rate on any estate running AD CS — legitimate CA administration produces this constantly. Never hunt on this alone |

**Build hunts on ranks 1-2 as primary detections — rank 1 is uniquely valuable because it survives even a total absence of process-creation logging. Treat rank 3 as a strong network-only corroborator. Treat ranks 4-5 as enrichment only.**

## Hunting on Source

Source-side hunting for this tool means pivoting through the infrastructure/tasking layer described in `03 - Source Evidence.md`, not an "operator machine" in the usual sense of this module:

```
# If attacker web-hosting infrastructure is ever recovered: grep access logs for the
# certutil-characteristic User-Agent strings — a list of every victim source IP that
# pulled from this URL
grep -E "Microsoft-CryptoAPI/10\.0|CertUtil URL Agent" access.log

# If C2 server task history is available (red-team retrospective, or recovered
# attacker infrastructure): search issued-command history for the certutil verbs
grep -iE "certutil.*(-urlcache|-verifyctl|-decode|-encode)" c2_task_history.log
```

See this module's `Sliver/`, `PowerShell Empire/`, and other C2-framework folders for how each framework's own task-history logging is structured, rather than re-deriving it here.

## Hunting on Target

```powershell
# 1. HIGHEST-CONFIDENCE, SURVIVES RENAME: CryptnetUrlCache side-effect artifacts —
#    fires for every download-verb invocation regardless of process name or
#    whether process-creation logging exists at all
Get-ChildItem "$env:LOCALAPPDATA\..\LocalLow\Microsoft\CryptnetUrlCache\MetaData" -ErrorAction SilentlyContinue
Get-ChildItem "$env:windir\ServiceProfiles\*\AppData\LocalLow\Microsoft\CryptnetUrlCache\MetaData" -ErrorAction SilentlyContinue

# 2. Command-line argument-shape hunt in Sysmon — survives a renamed/relocated binary
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=1} |
  Where-Object { $_.Message -match '(?i)-urlcache|-verifyctl\s+-f|-decode(hex)?\s|-encode(hex)?\s' } |
  Select-Object TimeCreated,
    @{n='Image';e={($_.Message -split "`n" | Select-String '^Image:').ToString()}},
    @{n='OriginalFileName';e={($_.Message -split "`n" | Select-String 'OriginalFileName:').ToString()}},
    @{n='CommandLine';e={($_.Message -split "`n" | Select-String 'CommandLine:').ToString()}}

# 3. Same argument-shape hunt against native Security 4688, if Sysmon isn't deployed
#    but command-line auditing IS enabled
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4688} |
  Where-Object { $_.Message -match '(?i)-urlcache|-verifyctl\s+-f|-decode(hex)?\s|-encode(hex)?\s' }

# 4. Path/location check: a certutil-signed binary (by OriginalFileName/Authenticode)
#    running from anywhere other than the two legitimate install paths
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=1} |
  Where-Object {
    $_.Message -match 'OriginalFileName:\s*CertUtil\.exe' -and
    $_.Message -notmatch 'Image:.*\\(System32|SysWOW64)\\certutil\.exe'
  }

# 5. Corroboration only — do NOT hunt on this alone (rank 5, weakest)
Get-Process -Name certutil -ErrorAction SilentlyContinue
```

## Fleet-Wide Sweep

```powershell
# Run from a hunting workstation with rights across the estate — the fleet-level
# signal is many hosts each independently generating the same certutil argument
# shape and/or a matching downloaded-file hash within a tight overall window
$targets = Get-Content .\hosts.txt

$results = Invoke-Command -ComputerName $targets -ScriptBlock {
  $sysmonHits = Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Sysmon/Operational'; Id=1} -MaxEvents 500 -ErrorAction SilentlyContinue |
    Where-Object { $_.Message -match '(?i)-urlcache|-verifyctl\s+-f|-decode(hex)?\s|-encode(hex)?\s' }

  $cacheHits = Get-ChildItem "$env:LOCALAPPDATA\..\LocalLow\Microsoft\CryptnetUrlCache\MetaData" -ErrorAction SilentlyContinue

  [PSCustomObject]@{
    Host              = $env:COMPUTERNAME
    SysmonHitCount    = ($sysmonHits | Measure-Object).Count
    LatestSysmonHit   = ($sysmonHits | Sort-Object TimeCreated -Descending | Select-Object -First 1).TimeCreated
    CryptnetCacheHits = ($cacheHits | Measure-Object).Count
  }
} -ErrorAction SilentlyContinue

$results | Where-Object { $_.SysmonHitCount -gt 0 -or $_.CryptnetCacheHits -gt 0 } |
  Sort-Object LatestSysmonHit -Descending

$results | Export-Csv -Path .\certutil_sweep_results.csv -NoTypeInformation
```

## Network-Layer Hunting

For environments with a network sensor (Zeek, Suricata, proxy logs) — especially valuable given rank-1/rank-3 signals in the priority table above don't require endpoint telemetry at all:

```
# Zeek: the certutil-specific User-Agent strings against any destination,
# independent of endpoint visibility
zeek-cut ts id.orig_h id.resp_h host uri user_agent < http.log |
  grep -E "Microsoft-CryptoAPI/10\.0|CertUtil URL Agent"

# Cross-reference the resulting destination host/URI against threat intel and
# against internal known-good CA/CRL/Windows-Update endpoints to cut noise fast
```

## Remediation

**Capture evidence first** — export the `CryptnetUrlCache\MetaData` entry (it carries the source URL and download timestamp on its own), the Sysmon 1/Security 4688 command-line record, and a copy of the downloaded/decoded file before removing anything, since the `MetaData` entry is often the only surviving record of *what URL was hit* if the operator used the ADS variant or otherwise obscured the output path.

```powershell
# Kill the process if caught live
Get-Process -Name certutil -ErrorAction SilentlyContinue | Stop-Process -Force

# Quarantine the downloaded/decoded payload — path recovered from the Sysmon 1
# CommandLine field or the CryptnetUrlCache MetaData entry
Move-Item "<RecoveredOutFilePath>" "C:\Quarantine\" -Force -ErrorAction SilentlyContinue

# Also check the CryptnetUrlCache Content copy, which persists independently
# of whatever the operator did with their own OutFile copy
Get-ChildItem "$env:LOCALAPPDATA\..\LocalLow\Microsoft\CryptnetUrlCache\Content" -ErrorAction SilentlyContinue

# Block the source URL/domain at proxy/firewall/DNS
```

Address whatever the downloaded/decoded payload actually was — a C2 agent, a ransomware stage, a credential stealer — using that payload's own dedicated tool folder in this module or the relevant `Windows/Threat Landscape and Playbooks/` playbook; this section covers only the certutil delivery step itself.

Real hardening — beyond evidence capture:

- **Enable command-line process auditing** (Security 4688 with command-line logging, or deploy Sysmon) — without it, rank-2 in the priority table above is entirely invisible, and only the network-only signals (ranks 1, 3) remain usable.
- **Constrain `certutil.exe` via AppLocker/WDAC** on hosts that have no legitimate CA-administration need for it — most endpoints in most estates never legitimately run this binary at all; a default-deny or alert-on-execution policy for it on non-PKI-admin workstations meaningfully shrinks this technique's usable footprint.
- **Alert on the argument shape, not the binary name** — per the priority table, the download/encode/decode verb pattern is the durable signal; a detection keyed only on `Image` = `certutil.exe` is defeated by the renamed-binary variant in `02 - Hands-On Use Cases.md`.
- **Proxy/firewall egress filtering with UA-aware inspection** — since the certutil-characteristic User-Agent strings are a network-only signal that survives every operator-side evasion documented in this note, an egress control that can alert or block on them (independent of destination reputation, which changes constantly) is a durable layer.
- **Treat a `CryptnetUrlCache` entry for a non-Microsoft, non-organizational-CA URL as a confirmed finding, not a maybe** — per `04 - Target Evidence.md`, this cache is written regardless of operator OPSEC choices around the explicit output path, making it one of the few artifacts in this note that's genuinely hard for the operator to suppress.
